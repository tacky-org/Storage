# Write errors

Write errors are caught by TanStack's mutation and exposed on `mutation.isError`
and `mutation.error`. No `<ErrorBoundary>` needed — the component stays mounted
and you can display the error inline next to the button that triggered it.

```tsx
const mutation = useStorageMutation(userPrefsStore);

return (
  <div>
    <button onClick={() => mutation.set({ theme: 'dark', language: 'en', notifications: true })}>
      Save
    </button>

    {mutation.isError && mutation.error instanceof StoragePipelineError && (
      <p>Write failed at step "{mutation.error.step}": {String(mutation.error.cause)}</p>
    )}
  </div>
);
```

Write errors always carry a `step` that tells you where in the pipeline it failed:

<table>
  <thead><tr><th>Step</th><th>Cause</th></tr></thead>
  <tbody>
    <tr><td><code>unmap</code></td><td>The <code>unmap</code> function threw — e.g. value failed a constraint</td></tr>
    <tr><td><code>write</code></td><td>The external store threw — e.g. <code>QuotaExceededError</code></td></tr>
  </tbody>
</table>
