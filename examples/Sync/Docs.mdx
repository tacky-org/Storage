# Sync — cached until changed

Storage queries are cached indefinitely (`staleTime: Infinity`).
A re-read is triggered only when the store signals a change.

## Cross-tab sync

When backed by `localStorage`, `useStorageSuspenseQuery` and `useStorageQuery`
subscribe to the browser's native `storage` event. Any write from another tab
invalidates the query and triggers a single re-read — no polling, no websockets.

Only components that call `useStorageSuspenseQuery` or `useStorageQuery` on that
store will re-render. Nothing else in the tree is affected.

`sessionStorage` is tab-scoped so no cross-tab events fire.

Open this example in two tabs and click a button in one — the other updates immediately.

## `useStorageSync`

`useStorageSuspenseQuery` and `useStorageQuery` call `useStorageSync` internally,
so you rarely need to call it directly.

It is exported for advanced cases where you need the subscription active before
the reading component has mounted — for example, pre-warming the cache during
app initialisation before a lazy-loaded route renders.

Note that `useStorageSync` itself does not cause re-renders. It only invalidates
the query, which causes components subscribed to that store to re-render.
